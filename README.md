# Проект "Электронный ловец фрода в реальном режиме"



## Описание проекта
 
Задачей проекта "Электронный ловец фрода" является создание системы для анализа транзакций в реальном времени с целью выявления мошенничества, в виде аномальных данных. Система использует данные о клиентах, их поведенческие данные и банковские операции, а также разрабатываются и оптимизируются алгоритмы для обработки данных. Основная цель — эффективное предотвращение финансовых преступлений.

## Используемые технологии

- Kafka (для потоковой доставки данных)
- Spark/Spark streaming (для обработки данных)
- Hadoop (для размещения и хранения данных)
- GreenPlum (для организации хранилища данных)
- ClickHouse (для организации витрин данных)
- Airflow (для оркестрации доставки данных)

## Логика архитектуры проекта

1) Генерируем файлы банковских транзакций, логирования и активности клиентов, их платежей для последующей потоковой обработки на предмет фрода. 
2) Загружаем данные в Kafka для получения данных в режиме потока и последующей передачи в SparkStreaming (real-time данные перекладываем с producer генератора на consumer spark).
3) В SparkStreaming происходит преобразование для укалыдвания данных в HDFS (прописана логика поиска фрода в потоке транзакций).
4) Опционально: Prometheus и Grafana могут быть использованы для сбора и анализа метрик, а также общего мониторинга передачи данных в рамках потокового пайплайна и поиска узких мест при повышениях нагрузки.
5) Выгружаем данные в HDFS для хранения: создаем долгосрочное хранилище всех данных с возможностью доступа других команд.
6) Через PXF, который осуществляет параллельную загрузку данных по сегментам, данные помещаются в GreenPlum, где создаются необходимые слои для формирования финальных витрин, данные обогащаются описательными данными, словарями.
7) Витрины данных из GP попадают в ClickHouse для дальнейшей аналитики (в некоторых случаях запросы, требующие больших вычислений и агрегаций, могут выполняться быстрее в ClickHouse из-за оптимизированной колоночной структуры хранения).
8) Опционально: можно реализовать напрямую загрузку real-time данных из Kafka в ClickHouse для отчетности.
9) Опционально: Superset может подключаться к ClickHouse для оперативного доступа к агрегированным данным и быстро формировать отчёты и дашборды.

## Пошаговое действие

### 1. generators 
Создаем генераторы данных о клиентах, клиентских активностях, логинах клиентов, платежах,  транзакциях в виде функций, распределенных по файлам .py.
### 2. kafka 
Сгенерированные CSV файлы размещаем на 5 топиках на Kafka. Каждый CSV-файл (таблица) помещается в отдельный топик, где каждая строка таблицы – отдельное сообщение топика. Реализуется посредством Producer библиотеки confluent_kafka. Данные в Kafka хранятся в виде сериализованного JSON-файла. 
Запуск скрипта осуществляется через командную строку:
```
python -m kafka.producer
```
### 3. spark
Извлекаем данные из Kafka через в HDFS посредством Spark на хранение в виде JSON и CSV файлов. В результате каждая таблица партиционируется по нескольким CSV-файлам и хранится на удаленном сервере HDFS. Например, таблица logins хранится в директории hdfs://172.17.0.23:8020/user/e.krylova/study_project_b/logins/csv_files
Чтобы посмотреть содержимое папки csv_files с данными о логинах пользователей, используем команду:
```
hdfs dfs -ls study_project_b/logins/csv_files
```
### 4. greenplum

Загружаем данные из HDFS в базу данных GreenPlum с использованием PXF внешней таблицы.

- RAW-слой: Все данные помещаются в сырой слой RAW, где данные будут храниться в своем первоначальном виде, как были извлечены из HDFS.
![Слой RAW](/images/RAW.jpg)
- ODS-слой: В слое ODS данные будут очищены от null-значений, а также от дублирующих и аномальных данных. Определение первичного ключа каждой таблицы.

- DDS-слой: В слое DDS данные будут обогащаться, а также будет построены связи между таблицами.

- DM-слой: Витрины данных с рассчитанными агрегатами и прочей аналитикой и статистикой.
