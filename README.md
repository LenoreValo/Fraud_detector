# Проект "Электронный ловец фрода в реальном режиме"



## Описание проекта
 
Задачей проекта "Электронный ловец фрода" является создание пайплайна для поставки и обработки данных для дальнейшего анализа транзакций в режиме реального времени с целью выявления мошенничества. Система использует данные о клиентах, их поведенческие данные и банковские операции, а также разрабатываются и оптимизируются алгоритмы для обработки данных и выявления аномальных данных.

## Используемые технологии

- Kafka (для потоковой доставки данных)
- Spark/Spark streaming (для обработки данных)
- Hadoop (для размещения и хранения неструктурированных данных)
- GreenPlum (для организации хранилища структурированных данных)
- ClickHouse (для организации витрин данных)
- Airflow (для оркестрации доставки данных)

## Логика архитектуры проекта

1)	Генерация данных банковских транзакций, логирования и активности клиентов, их платежей для последующей потоковой обработки на предмет фрода.
2)	Загрузка данных в топики Kafka для получения данных в режиме потока и последующей передачи в SparkStreaming.
3)	Преобразования в SparkStreaming для последующего укладывания данных в HDFS.
4) Опционально: Prometheus и Grafana могут быть использованы для сбора и анализа метрик, а также общего мониторинга передачи данных в рамках потокового пайплайна и поиска узких мест при повышениях нагрузки.
5)	Выгрузка данных в HDFS для их долгосрочного хранения.
6)	Через PXF, который осуществляет параллельную загрузку данных по сегментам, данные помещаются в GreenPlum, где создаются необходимые слои для формирования финальных витрин, данные обогащаются описательными данными, словарями.
7)	Загрузка витрин данных из GP в ClickHouse для дальнейшего анализа.
8)	Создание DAG в Airflow для автоматизации выполнения, мониторинга и оркестровки потоков операций по обработке данных.
9) Опционально: можно реализовать напрямую загрузку real-time данных из Kafka в ClickHouse для отчетности.
10) Опционально: Superset может подключаться к ClickHouse для оперативного доступа к агрегированным данным и быстро формировать отчёты и дашборды.

## Пошаговое действие

### 1. generators 

Создаем генераторы данных о клиентах, клиентских активностях, логинах клиентов, платежах,  транзакциях в виде функций, распределенных по файлам .py.

### 2. kafka 

Сгенерированные CSV файлы размещаем на 5 топиках на Kafka. Каждый CSV-файл (таблица) помещается в отдельный топик, где каждая строка таблицы – отдельное сообщение топика. Реализуется посредством Producer библиотеки confluent_kafka. Данные в Kafka хранятся в виде сериализованного JSON-файла. 
Запуск скрипта осуществляется через командную строку:
```
python -m kafka.producer
```
### 3. spark

Извлекаем данные из Kafka через в HDFS посредством Spark на хранение в виде JSON и CSV файлов. На данном этапе убираются записи с NaN значениями в ключевых столбцах таблиц, а также конвертируются поля с датой из типа String в тип Datetime. В результате каждая таблица партиционируется по нескольким CSV-файлам и хранится на удаленном сервере HDFS. Например, таблица logins хранится в директории hdfs://172.17.0.23:8020/user/e.krylova/study_project_b/logins/csv_files

Чтобы посмотреть содержимое папки csv_files с данными о логинах пользователей, используем команду:
```
hdfs dfs -ls study_project_b/logins/csv_files
```
### 4. greenplum

- RAW-слой: Загружаем данные из HDFS в базу данных GreenPlum с использованием PXF. Все данные помещаются в сырой слой RAW во внешние таблицы, где данные будут храниться в своем первоначальном виде, как были извлечены из HDFS.

![Слой RAW](/images/RAW.jpg)

- ODS-слой: Загрузка данных из RAW, приведение полей к нормальным типам данных. Очистка от дублирующих строк.

![Слой ODS](/images/ODS.jpg)

- DDS-слой: Очистка от аномальных данных (аномальные даты), а также избавление от записей с null-значениями и дублями в ключевых столбцах. Обогащение данных, нормализация, построение связей между таблицами по схеме "Звезда".

![Слой DDS](/images/DDS.jpg)

- DM-слой: Витрины данных с рассчитанными агрегатами и прочей аналитикой и статистикой.

![Слой DM](/images/DM.jpg)

### 5. clickhouse

Мигрируем все таблицы GreenPlum слоя DM в ClickHouse для дальнейшего анализа данных. Для этого создаем вначале внешнюю таблицу в ClickHouse с ссылкой на таблицу в GreenPlum через параметр ENGINE, затем создаем локальную таблицу ClickHouse и загружаем данные из внешней таблицы в локальную через insert.
